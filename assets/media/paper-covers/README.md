## HEAR graphical-abstract sample

`hear-graphical-abstract-base-v2.png` was generated with the built-in image-generation tool from the paper's authoritative Figure 1 concept image and Figure 2 architecture image. The local reference renders are `artifacts/paper-figures/hear-fig1.png` and `artifacts/paper-figures/hear-fig2.png`, derived respectively from `/DataBig/hear_ijrr/images/headpic.pdf` and `/DataBig/hear_ijrr/images/overview.pdf`. The generated layer provides the clean visual system; `scripts/build-publication-covers.mjs` overlays all exact terminology and explanatory text. Final prompt:

> Use case: scientific-educational. Asset type: 16:9 graphical abstract for a robotics research paper on an academic website. Input images: Image 1 is the authoritative concept reference (sound-centric task, VLA-to-VSLA timing challenge, Blind Execution Interval, overall HEAR solution). Image 2 is the authoritative architecture reference (inputs, Historizer, Envisioner, training-only Advancer branch, Realizer, action chunk). Synthesize and simplify their scientific content; do not copy their existing typography or dense panel layout. Primary request: Create a clean white-background, two-dimensional scientific infographic base that explains HEAR in one continuous visual. At the upper left, show a streaming audio waveform with one short salient sound pulse occurring inside a lightly indicated open-loop execution interval, before the next policy decision. Make visually clear that the original pulse ends but a compact memory representation carries it forward. Across the central horizontal flow, show four visually distinct but connected mechanisms: packetized causal audio memory; multimodal fusion of camera views, language instruction, robot state, and audio context; a small training-only near-future audio-prediction branch; and smooth action-chunk generation leading to a robot arm executing the next action. The causal memory must connect into multimodal reasoning, the audio-prediction branch must read from the semantic representation without appearing at deployment, and the action generator must receive the control representation. Style/medium: polished flat 2D vector-like scientific illustration, crisp thin strokes, restrained geometric icons, journal graphical-abstract quality, clean and modern without looking like a slide template. Composition/framing: wide landscape 16:9; primarily left-to-right flow; generous white space; clear hierarchy; one integrated diagram rather than separate presentation cards. Leave calm whitespace directly above or below each mechanism for exact labels to be overlaid later. Color palette: white background; dark navy-gray outlines and text-safe areas; restrained blue for causal memory, teal for multimodal reasoning, amber for future-audio prediction, and coral red for action generation; no large color fields. Technical constraints: preserve the causal order and training-only status described above; do not invent modules, datasets, metrics, or robot capabilities. Use simple camera, microphone/waveform, speech/instruction, joint-state, transformer-memory, predicted-waveform, flow-curve, action-chunk, and robot-arm motifs only. Text constraints: absolutely no words, letters, numbers, equations, pseudo-text, placeholder glyphs, or watermarks; all exact typography will be added deterministically afterward. Avoid: 3D rendering, glossy surfaces, gradients, neon, glow, holograms, glass panels, sci-fi dashboards, advertising polish, dramatic lighting, photorealism, hand-painted texture, paper texture, slide title, giant acronym, oversized title area, dense small details, rounded app-style cards, floating UI, decorative particles.
